# Flash Metal performance optimization design

Optimize real Flash prefill on Apple Silicon while retaining the pinned artifact revision, request semantics and existing numerical limits (maximum probability error 1e-3, mean 1e-4). CPU F32 remains a portable reference. Performance claims require completed measurements on the user's MBP.

## Execution

Compile a checked F32 DeltaNet shader once per backbone load and share its pipeline across the 24 linear layers. Inputs are normalized F32 q/k and F32 v/decay/beta; exponentiate decay once per token/head before packing. Specialize the power-of-two key width at pipeline creation so private state arrays stay in registers. Preserve the reference block reduction tree `(0+64)+(32+96)` before the SIMD sum to protect subsequent F16 rounding boundaries. Each SIMD group owns one value column, keeps up to four key states per lane, and traverses the bounded sequence entirely on GPU. Uncached state starts at zero on each layer. One launch replaces the token loop. Optional exact prefill continuation is specified separately in [the prefix-reuse contract](clef-prefix-reuse-design.md). Four independent SIMD groups form a 128-thread group. Validate dimensions (1–4,096 tokens, 1–32 heads, power-of-two key width up to 128, value width up to 128), input shapes, dtype, contiguous offsets and buffer byte ranges before dispatch.

Use F32 SDPA for full attention without expanding GQA KV heads. For the Flash 256-dimensional head, instantiate the pinned dependency's algorithm with 16-query/8-key tiles so its 28,928-byte shared storage fits Apple GPU limits. All 16/8 sequence alignment combinations have shared precompiled pipelines; causal masking, GQA, tail handling and the explicit 160-byte parameter ABI are verified. Classifier/vision attention and synthetic fixture widths retain the qualified tiled reference, including on Metal; only the backbone full-attention layers use the optimized pipeline. Projection precision and F32-sensitive components do not change.

On Apple GPU family 10, large F16 backbone projections use Metal 4 MPP matrix operations. Compile shared 64×64 and 64×128 pipelines at load, using four SIMD groups, static extents for complete tiles and dynamic bounds for tails. Select the wide tile for at least 2,048 rows, the 12,288-wide FFN down projection, or at least 256 rows with at most 8,192 output columns; measured short FFN expansion retains 64×64. Accumulate in F32 with relaxed precision disabled, convert the cooperative result to half and store it directly. This removes a temporary F32 output and conversion dispatch. Validate contiguous byte ranges and bounded M/N/K dimensions before dispatch. Tiny 32-output decay/beta projections, F32 profiles and older GPU families retain the existing matrix path. Vision and classifier projections remain F32 on their qualified path.

Precompute offset RMS weights in F32 at load. Share checked F32 RMSNorm and four-tap causal convolution pipelines across backbone layers. RMSNorm preserves the reference loader, block/SIMD reduction tree, mean scaling, separate square-root/reciprocal rounding, and output dtype boundary. A volatile square-root result prevents compiler replacement by approximate reciprocal square root. Support power-of-two widths up to 4,096 and at most 16,777,216 elements; validate dtype, contiguous layouts and buffer ranges. Convolution accepts 1–4,096 tokens and 1–8,192 channels with exactly four weights per channel, accumulates oldest to newest without contraction, and keeps the existing SiLU operation. Unsupported thread geometry retains the original Metal graph. CPU uses the original equations with precomputed offset parameters.

Candle owns buffers, command lifetimes and hazard tracking. Production Rust forbids unsafe code. Compilation, dispatch and device completion errors propagate through existing model errors. Cancellation/deadlines are checked before and after submission and between layers; queued device work completes through the existing owner-thread lifecycle. No synchronous host readback is added to normal inference.

## Long-prefill execution

On Apple GPU family 10, specialize the 128-key/128-value DeltaNet recurrence for four independent value columns per SIMD group. Each lane holds four vectors of F32 key states; q/k/decay loads are shared within the vector. Keep the exact per-column arithmetic and reduction tree. Four SIMD groups form one 128-thread group, covering 16 value columns. Other shapes/GPU families retain the single-column specialization. Bounds and owner-thread lifecycle are unchanged.

For M5 mixed-F16 sequences of at least 512 tokens, fuse the FFN gate/up projections, SiLU and product in one checked 64×128 MPP dispatch. Reuse one F32 accumulator, retain the gate activation in a half cooperative tensor, and preserve all separate half rounding boundaries. Accept separate unchanged gate/up weight buffers, validate their equal shapes and bounded contiguous offsets, and store only the final half FFN intermediate. Smaller requests, biased projections, CPU, F32 and older GPU families use the existing operations. No new weight copy or relaxed precision is permitted.

Retain the qualified two-dimensional projection grid and dynamic K extent. Explicit launch walks/K blocks remain diagnostic candidates. The mathematically complete 32-token F32 chunkwise DeltaNet candidate is compiled only into test binaries; local performance regressions disqualify it from serving. It is not advertised as a qualified release backend. `profile-metal-ffn`, `profile-metal-long-gemm` and `profile-metal-chunk` reproduce these candidate measurements.

## Verification and measurement

Test recurrence against CPU across SIMD/key/value tails and supported key widths, and check drift against the previous Metal reduction within 1e-7. Test causal GQA and cross attention against the tiled CPU reference, including vector, unaligned and multi-tile lengths. Verify full Flash text, long context, PNG, JPEG, CLI, authenticated HTTP, provenance and shutdown in both precisions. Check both Metal 4 projection tiles against CPU F32 accumulation followed by half rounding, including partial tiles and unaligned K. Check fused gate/up/SiLU/product against separate GPU operations with exact half equality, covering grouped-walk tails, bounded offsets and rejected malformed inputs. Check RMSNorm F32 error and exact half rounding, exact convolution equality across causal tails, and rejected invalid dispatch inputs. `make verify-metal-neural` requires an M5/Apple GPU family 10 device; `make verify-metal-pointwise` requires Metal. Run existing build/test/format/Clippy gates; retain dependency policy checks when applicable.

Preserve the previous raw CPU/Metal and M5 baselines. `make bench-mbp` records all original workloads plus 139/192-token requests, with exact encoded lengths, warmups, 100 direct samples per profile and concurrency 1/2/8/16. Model processes run sequentially. Compare normal-path means on matching workloads; do not use traced or barrier-added diagnostics as throughput estimates. Keep raw samples, memory metrics, executable/workload hashes and explicit small-sample limitations. `make profile-metal` captures Instruments traces outside source control; `make profile-metal-kernels` isolates recurrence diagnostics. `make profile-metal-tiles` measures candidate matrix geometry; `make profile-metal-backbone` records nested inclusive/exclusive categories on synthetic token sequences. Diagnostic barriers and owner-thread timing state compile only into test binaries. Categories do not cover every residual/activation operation. CPU full-weight performance is reused from the existing campaign because the CPU equations are unchanged.
