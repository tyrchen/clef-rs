# Flash Metal performance evidence

Checked 2026-10-02 on the local 64 GiB Apple M5 Pro (20 GPU cores). Read the [previous backend research](clef-metal-benchmark-research.md) first. No dependency upgrades are needed: direct access uses the already locked Candle Metal kernels 0.11.0 and objc2-metal 0.3.2.

A Metal System Trace of the immutable pre-optimization executable showed many short compute encoder intervals. The source explains the submission growth: each of 24 DeltaNet layers issues tensor operations inside a token loop; at 4,096 tokens this dominates prefill. Profiling used Instruments, with raw traces outside the repository because they can contain unrelated system process information. Traced latency is not used as a normal performance sample. The 60-second baseline recording ended before managed-runtime completion; only its completed direct-phase samples and trace are diagnostic evidence.

The [exact Candle CustomOp interfaces](https://github.com/huggingface/candle/blob/31f35b147389700ed2a178ee66a91c3cc25cc80d/candle-core/src/custom_op.rs) permit safe Metal storage/layout dispatch. Published safe wrappers retain buffers and track encoder hazards. The fused kernel uses F32 private recurrent states and SIMD sums. Each SIMD group owns one value column; up to four key-state elements live in each lane. This removes per-token dispatches, intermediate state buffers and cross-group barriers. The first shared-memory implementation measured 7.611/31.301/130.884 ms per layer at 256/1,024/4,096 tokens; the subsequent SIMD version measured 3.696/11.710/47.137 ms in an initial diagnostic run. The final diagnostic after precomputing each token/head decay, specializing key width and restoring the reference reduction tree measured 2.082/5.583/21.856 ms per layer. These three-sample operator timings are not full-model latency or a tail estimate.

The [Candle SDPA implementation](https://github.com/huggingface/candle/blob/31f35b147389700ed2a178ee66a91c3cc25cc80d/candle-nn/src/ops.rs) supports GQA and causal attention, avoiding repeated KV heads and tiled softmax intermediates. Its F32 head-width-256 pipeline fails to create on this GPU. Inspection of the [upstream shader](https://github.com/huggingface/candle/blob/31f35b147389700ed2a178ee66a91c3cc25cc80d/candle-metal-kernels/src/metal_src/scaled_dot_product_attention.metal) establishes the cause: the 32-query/16-key tile allocates 53,760 bytes of threadgroup storage, beyond the 32 KiB limit. Instantiating the same public shader source with 16 queries, eight keys and two SIMD groups needs 28,928 bytes. The implementation adds an instantiation to the dependency-provided source rather than maintaining a fork. It shares four alignment-specialized pipelines across all eight backbone attention layers. Both q/k/v and accumulation remain F32; this is not a half-precision substitute for the F32 profile.

[Apple's porting guidance](https://developer.apple.com/documentation/apple-silicon/porting-your-metal-code-to-apple-silicon) motivates explicit threadgroup memory accounting and SIMD collectives. The implementation validates every dimension, dtype, contiguous layout, checked byte range, output shape and fixed ABI layout before submitting custom work. Pipelines compile once at model load. The classifier/vision attention and small synthetic fixture widths retain the existing GPU tensor graph. Routing the F32 vision tower through generic SDPA passed operator tests but exceeded the mixed-F16 full-image mean probability gate (0.000124866); the sensitive vision input is therefore kept on the qualified reference path.

The SIMD recurrence initially used a sequential four-part sum. Inspection of Candle's block reduction showed that the 128-key reference groups products as `(0+64)+(32+96)` before its SIMD sum. Preserving that tree is necessary: tiny F32 differences otherwise cross subsequent F16 rounding boundaries. A representative fused result is checked against the previous Metal recurrence within 1e-7, in addition to CPU checks. The restored tree brought the extended mixed-F16 image/context mean error back to 0.000052260 (limit 0.0001) without widening a gate.

The CPU tensor equations remain the reference. Numerical qualification uses existing Python F32 full-model text/long-context/PNG/JPEG oracles and unchanged maximum/mean probability thresholds. Performance qualification uses the existing six exact workloads plus 139/192-token compact inputs, separate F32/F16 processes, all raw samples, allocator/process metrics and bounded concurrent admissions. No FP8 execution or hardware latency guarantee is inferred from these changes.

## M5 projection evidence

Inspection of the pinned `mlx_gemm.metal` found that its F16 path promotes matrix operands to F32 SIMD matrices. [Apple’s Metal 4 inline operations](https://developer.apple.com/documentation/metal/running-inline-ml-operations-in-a-shader-with-metal-4) and [MPP programming guide](https://developer.apple.com/download/files/Metal-Performance-Primitives-Programming-Guide.pdf) provide tensor matrix operations for M5 GPU neural accelerators. The guide recommends starting with four SIMD groups and 32×32 tiles per group, using static extents for complete tiles. Our kernel uses that 64×64 group tile with dynamic bounds at the edges.

The implementation accepts existing row-major half buffers, retains F32 accumulation with relaxed precision disabled, writes a F32 result, and uses the existing GPU half conversion. The right operand stays physically K×N with the transpose descriptor enabled; a strided logical N×K view did not preserve the required tensor layout. Input pointers are read-only in the shader body. No host tensor-resource allocation, weight repacking or CPU fallback is required. Compilation is restricted to Apple GPU family 10 and F16 backbone projections; older GPUs retain the qualified Candle Metal path.

On this MBP, three synchronized samples of 139/256/1,024-row projections (12,288 outputs, 4,096 inputs) measured 1.365/1.621/6.065 ms with MPP versus 4.865/4.239/14.037 ms with the existing kernel. These operator diagnostics establish a reason to test the complete model; they are not full-model performance claims. Numerical tests include K/M/N tails and complete tiles. Full-model probability qualification remains mandatory. This is F16 input with F32 accumulation, and supplies no FP8 qualification.

## Shape and pointwise tuning

The follow-up local campaign on 2026-10-02 (2026-10-03 UTC) profiled nested backbone categories with barriers before modifying them. At 4,096 synthetic tokens, matrix projection and normalization categories took 3,683 and 1,177 ms respectively under this instrumentation. These are diagnostic observations: barriers change scheduling, categories omit some activation/residual work, and they are not normal-path percentages.

The MPP cooperative tensor supports element conversion before its store, so the shader now rounds its F32 accumulator directly into a half cooperative result. The [Apple MPP guide](https://developer.apple.com/download/files/Metal-Performance-Primitives-Programming-Guide.pdf) also motivates measuring tile shapes. Six geometries were swept across five Flash projection shapes and four sequence lengths. Three synchronized samples per shape showed a 64×128 tile reducing 4,096-row FFN expansion from 21.746 to 16.675 ms, FFN contraction from 23.874 to 15.080 ms, and the 8,192-output projection from 13.310 to 9.999 ms versus fused 64×64. Short expansion retains the smaller tile. These finite synthetic operator measurements guide shape selection; the full workload matrix determines performance claims.

Inspection of the pinned Candle `reduce.rs`/`reduce.metal` established the normalization loader, 1,024-thread cap, block reduction and SIMD sum; its `tensor.rs` scales the sum to a mean. The old graph computes square root and reciprocal in separate kernels. Initially fusing them allowed reciprocal-square-root substitution and crossed half rounding boundaries. Retaining the square-root result in a volatile local preserves that boundary. The final kernel passes F32 comparison within 1e-6 and exact half-rounding checks for widths 1/4/128/256/4,096 and rows 1/17/139. Four-tap convolution preserves oldest-to-newest multiplication/addition without contraction and passes exact F32 comparison across 1/2/3/4/17/139 tokens and up to 8,192 channels. Both kernels validate their bounded dispatch inputs and remain in F32; full-model text, context, PNG and JPEG qualification is still required.
